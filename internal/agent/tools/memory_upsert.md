Create or replace one persistent memory through the managed memory service.

Before calling this tool, use `memory_list` to inspect the target scope. If a related memory exists and remains relevant, update that topic with the new durable information instead of creating another topic. Remove related memories that are no longer relevant, stale, or superseded. Each project has a hard limit of 50 memory slots, one per topic file; the managed index does not occupy a slot. Keep titles and relevance hooks brief in the index and store details in the linked topic files. Consolidate related facts into existing topics instead of creating one file per fact. At capacity, new topics fail clearly: merge related memories, preserve their useful details, and remove superseded files before adding another. Existing over-limit collections remain readable and editable but cannot add new topics until within the limit. User-wide memory is separate. This is an application-state operation, not a generic workspace file edit, and remains available when workspace mutation tools are disabled. Use a stable semantic topic ID. Do not save secrets, repository-derived code structure, transient task state, or facts already represented by current code and documentation.
