Create or replace one persistent memory through the managed memory service.

Before calling this tool, use `memory_list` to inspect the target scope. If a related memory exists and remains relevant, update that topic with the new durable information instead of creating another topic. Remove related memories that are no longer relevant, stale, or superseded. Keep each scope naturally concise, aiming for roughly 30 to 50 memories depending on project complexity as a soft target rather than a hard limit. This is an application-state operation, not a generic workspace file edit, and remains available when workspace mutation tools are disabled. Use a stable semantic topic ID. Do not save secrets, repository-derived code structure, transient task state, or facts already represented by current code and documentation.
